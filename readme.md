## Порівняння ефективності алгоритмів

### Жадібний алгоритм

Жадібний алгоритм проходить по списку монет один раз і для кожної монети визначає, скільки разів її можна використати для поточної суми.

Часова складність: `O(n)`, де `n` — кількість номіналів монет.

Цей алгоритм дуже швидкий і добре працює навіть для великих сум, тому що кількість операцій залежить не від значення `amount`, а тільки від кількості монет у списку.

Однак жадібний алгоритм не завжди гарантує мінімальну кількість монет і може дати неоптимальний результат.

### Алгоритм динамічного програмування

Алгоритм динамічного програмування обчислює мінімальну кількість монет для кожної суми від `1` до `amount`. Для кожної поточної суми він перебирає всі доступні монети та шукає найкращий варіант.

Часова складність: `O(n * m)`, де `n` — кількість номіналів монет, а `m` - сума, яку потрібно набрати.

Цей алгоритм працює повільніше на великих сумах, тому що кількість операцій напряму залежить від значення `amount`.

Проте головна перевага динамічного програмування полягає в тому, що воно завжди знаходить оптимальне рішення, якщо таку суму можна скласти з доступних монет.

### Висновок

Жадібний алгоритм є значно швидшим і ефективнішим за часом, особливо для великих сум, але він не завжди гарантує мінімальну кількість монет.

Алгоритм динамічного програмування має більшу часову складність, тому працює повільніше при великих значеннях `amount`. Проте він є надійнішим, оскільки завжди знаходить мінімальну кількість монет для заданої суми.
